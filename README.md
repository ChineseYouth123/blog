# 文件推送

在子模块（`src/blog`）中提交代码，和在一个完全独立的普通 Git 仓库里提交是一模一样的。

但**最关键、最容易出错的一步是**：在子仓库提交并推送后，你必须回到外层的主仓库（`~/test/notes`），把主仓库记录的“子模块指针”也更新一下并推送，否则远程主仓库根本不知道你子仓库更新了。

请严格按照以下流程操作：

### 第一阶段：在子仓库（`src/blog`）中提交

假设你现在已经把丢失的文件找回来并放进 `src/blog` 目录了。

**1. 进入子仓库目录**

```bash
cd src/blog
```

**2. 确认当前在正确的分支上**

```bash
git branch
```

_确保输出中带有星号的是 `main` 或 `master`（不要处于分离头指针状态）。如果不在，执行 `git checkout main`。_

**3. 添加并提交文件**

```bash
git add .
git commit -m "docs: 恢复并整理所有文档文件"
```

**4. 推送到远程子仓库**

```bash
git push origin main
```

_到这里，你的文档代码已经安全地上传到 GitHub 的子仓库里了。_

---

### 第二阶段：在外层主仓库中更新指针（绝对不能漏！）

子仓库推送成功后，你要告诉外层主仓库：“嘿，我的文档仓库前进了，你记录一下最新的版本”。

**1. 返回主仓库根目录**

```bash
cd ../..
```

_(此时你的路径应该是 `~/test/notes`)_

**2. 检查主仓库状态**

```bash
git status
```

_你应该会看到类似这样的提示：_

> 位于分支 main
> 尚未暂存以备提交的变更：
> 修改： src/blog (new commits)

**3. 添加并提交子模块指针**

```bash
# 把新的子模块指针加入暂存区
git add src/blog

# 提交外层主仓库
git commit -m "chore: 更新 src/blog 子模块指针到最新版本"
```

**4. 推送到远程主仓库**

```bash
git push origin main
```

---

### 总结

整个流程的逻辑就是：
**进子目录 → `add` → `commit` → `push` → 退主目录 → `add src/blog` → `commit` → `push`**。

只要保证这两次 `push`（子仓库一次，主仓库一次）都成功，你的 GitHub Actions 就会自动拉取最新的代码和文档进行构建部署。如果操作过程中遇到冲突报错，再随时发出来。
